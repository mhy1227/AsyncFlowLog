▌ 看着很牛掰 但是假如项目被使用的话 需要放在什么模块呢  怎么去调用到我们的这个异步日志呢?

> 前置说明：

- 基于前面梳理的源码结构，整理集成方式与调用步骤，未对仓库做任何修改。

要让别的 Spring Boot 项目使用 AsyncFlowLog，可以按“引入依赖 → 配置参数 → 注入服务 → 按需扩展”这条路径来落地：

- 模块放置与依赖：当前代码本身就是一个可发布的 Maven 模块（pom.xml 在根目录）。把它打包成 jar 发布到内部仓库，业务工程在 pom.xml 里加入依赖，例如：

  <dependency>                                                                                                                                                                                                                    
      <groupId>com.example</groupId>                                                                                                                                                                                              
      <artifactId>asyncflowlog</artifactId>                                                                                                                                                                                       
      <version>1.0.0</version>                                                                                                                                                                                                    
  </dependency>                                                                                                                                                                                                                   
  只要业务工程的 @ComponentScan 能扫到 com.asyncflow.log 这个包（或者直接使用 Spring Boot 默认扫描），容器就会把事件工厂、队列、消费者线程池、写入器等 Bean 都组装好。

- 配置开箱即用参数（application.yml）：

  async:                                                                                                                                                                                                                          
  log:                                                                                                                                                                                                                          
  queue:                                                                                                                                                                                                                      
  type: linked        # 目前支持 linked，即 LinkedBlockingQueue                                                                                                                                                             
  capacity: 10000                                                                                                                                                                                                           
  consumer:                                                                                                                                                                                                                   
  core-size: 2                                                                                                                                                                                                              
  max-size: 4                                                                                                                                                                                                               
  keep-alive: 60                                                                                                                                                                                                            
  appender:                                                                                                                                                                                                                   
  type: file                                                                                                                                                                                                                
  file-path: /var/log/async                                                                                                                                                                                                 
  file-name-pattern: async-log-%s.log                                                                                                                                                                                       
  batch-size: 100                                                                                                                                                                                                           
  flush-interval: 1000                                                                                                                                                                                                      
  这些属性分别会喂给 QueueFactory、ConsumerFactory、AppenderFactory，你可以根据业务量调整队列容量、线程数或者日志落盘路径。
- 调用方式：
    1. 直接注入服务：在业务代码中 @Autowired AsyncLogService，调用 info/warn/error/log 等方法即可异步投递事件。README 中已经有一个控制器示例（README.md:54-83）。所有日志事件都会先走 LogEventFactory 构造 LogEventDTO，再由服务入
       队，后台线程负责写入文件。
    2. AOP/注解扩展：项目内还有操作日志模块（docs/AOP），如果需要业务审计，可在业务方法上打 @OperationLog，由切面自动采集上下文并通过同一个异步链路入库/入文件，这部分可以按需启用。
    3. API/监控查询：根据工程现状，还可以调用监控类 Bean 获取队列使用率、消费者线程活跃数等指标，用于运维面板或报警（涉及 getQueueSize()、getActiveThreadCount() 等接口）。
- 目录/模块划分建议：
    - 如果你打算让 AsyncFlowLog 作为独立组件长期复用，可以在业务项目里单独建一个 logging 或 infrastructure 模块，把这个 jar 依赖进来；或者进一步包装成 Spring Boot Starter（提供自动配置类和 spring.factories），让引入者只需要依
      赖 + 配置就能用。
    - 若业务项目想二次开发（比如把 FileAppender 换成 MQ / DB / ES），可以在自己的模块里实现 LogAppender 接口，然后通过配置或自定义 AppenderFactory 覆盖默认 Bean。
- 集成注意点：
    - 运行环境需使用 JDK 21（项目依赖虚拟线程等特性，详见 README.md:28-33）。
    - 确保部署机器上的日志目录有写权限；如需跨节点集中管理，可把 file-path 指定到共享挂载或进一步扩展 appender。
    - 异步链路默认在应用进程内运行，没有持久化队列，适合“高吞吐→快速落盘”的场景。若对可靠性要求更高，可在此基础上接入外部 MQ / 数据库实现多副本存储。

这样接入后，业务侧只需调用 AsyncLogService，就可以享受“生产者-队列-消费者-写入器”整套异步日志流水线，既不阻塞主线程，也保留了扩展、高性能和监控能力。
