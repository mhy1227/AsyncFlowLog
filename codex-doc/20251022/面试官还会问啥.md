可能追问点：

- 架构深挖：为什么选 LinkedBlockingQueue？有没有考虑 Disruptor、RingBuffer、虚拟线程等替代？线程池参数如何确定？
- 可靠性策略：服务宕机/队列满/写入失败时如何处理？有没有幂等、重试、降级方案？
- 性能调优经验：遇到过日志洪峰吗？如何压测？如何定位瓶颈（CPU、I/O、锁竞争）？
- 监控与运维：暴露了哪些指标？如何接入 Prometheus/Grafana？有没有报警阈值？
- 数据安全与合规：敏感信息如何脱敏？如何控制访问权限？日志加密/签名有没有考虑？
- 与现有框架集成：能否兼容 Logback/Log4j？如何写桥接 Appender？如何与 ELK、Splunk 等日志平台对接？
- 数据库功能场景：启用 log_file / log_index 表时的查询模式？如何做归档、清理？会不会拖慢数据库？
- 扩展路线：未来打算怎样支持 MQ、多通道、多租户？是否考虑提供 Starter 或 SaaS 化？
- 测试与质量保证：有哪些单测/集成测试？如何模拟队列满、写入失败、线程池崩溃的场景？
- 实际落地案例：这个框架在团队里用了多久？有无线上事故或重大收益案例？遇到的问题怎么解决的？

面试官常问的主题与示例：

1. 项目定位与价值
    - 为什么要自研 AsyncFlowLog，而不是直接用 Logback AsyncAppender / Kafka 等现成方案？
    - 项目上线后带来了哪些具体收益或指标提升？
2. 架构设计细节
    - 日志事件、队列、线程池、写入器之间是如何解耦的？模块边界在哪里？
    - LinkedBlockingQueue、ThreadPoolExecutor 的选择依据是什么？是否考虑过 Disruptor、虚拟线程？
3. 可靠性与容错
    - 服务宕机/重启、队列满、写入失败时如何处理？有没有重试、降级或补偿机制？
    - 如何确保日志不丢失或者可追溯？幂等策略是什么？
4. 性能调优
    - 做过哪些压测？吞吐量大概能达到多少？如何调参（队列容量、线程池大小、批量写入等）？
    - 遇到性能瓶颈时是如何排查的（CPU、I/O、锁竞争等）？
5. 监控与运维
    - 暴露了哪些监控指标？如何接入 Prometheus / Grafana？

- 线上如何报警？日志系统异常时如何快速发现？

6. 扩展与集成
    - 如果要把日志写到 Kafka / RabbitMQ / ES，具体需要改哪些代码、配置？
    - 有没有计划把项目做成 Spring Boot Starter 或开源 SDK？如何兼容 Logback/Log4j？
7. 数据库/操作日志部分
    - log_file / log_index / log_archive 字段如何使用？如何清理归档？性能是否有影响？
    - 操作日志的脱敏、安全、合规怎么保证？
8. 测试与上线
    - 编写了哪些单元/集成测试？如何模拟异常场景（如队列满、写入失败、线程池崩溃）？
    - 日志系统上线时如何灰度、回滚、保障稳定？
9. 真实案例与反思
    - 曾经遇到过哪些线上事故或挑战？如何解决？
    - 如果重新设计，你会改进哪些地方（比如可靠性、可观测、扩展性）？
